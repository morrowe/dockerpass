# Анкеты и бинарный поиск ID

## Запуск
Из корневой папки проекта выполните:

```bash
docker compose up --build
```

Форма: http://localhost:3000  
Бинарный поиск ID: http://localhost:3000/guess  
PostgreSQL с компьютера: localhost:5435, база `form`, пользователь `postgres`, пароль `postgres`.  
Redis с компьютера: localhost:6379.

При первом создании базы `database/init.sql` создаёт таблицы, а 1001 тестовую запись с ID от 1 до 1001 генерирует Faker (`database/seed.js`, русская локаль: ФИО, место и дата рождения, пол, телефон и паспортные данные). Если в таблице уже есть записи, генерация пропускается. Новые анкеты получают следующий ID.

Форма содержит разделы «Личные данные» и «Паспортные данные». В личных данных находятся фамилия, имя, отчество, место и дата рождения, пол и номер телефона. Поля адреса и email удалены из формы и базы данных. Каждая отправка создаёт отдельную заявку. Для связи с предыдущими обращениями проверяются совпадения по номеру телефона, серии и номеру паспорта, фамилии и имени с датой рождения либо имени и отчества с датой рождения. Предыдущие заявки не перезаписываются.

При запуске сервер базы данных удаляет устаревшие столбцы `email`, `registration` и `actual_address` из существующего Docker-тома, сохраняя остальные данные. Пересоздавать том не требуется.

Для полностью чистого запуска с повторной генерацией 1001 записи через Faker (это удалит текущие данные проекта):

```bash
docker compose down -v
docker compose up --build
```

## Структура базы данных

- `requests` — каждое обращение, раздельные поля фамилии, имени и отчества, телефон и последовательный ID. `person_id` одинаков у заявок, распознанных как обращения одного человека; первая заявка группы содержит собственный ID.
- `passports` — паспортные поля; `request_id` связывает паспортную запись с заявкой. Удаление заявки каскадно удаляет связанную паспортную запись.
- При сохранении формы заявка и паспортная запись создаются в одной транзакции, если переданы паспортные данные.

Чтобы посмотреть заявки, связанные с человеком, подключитесь к PostgreSQL и выполните запрос, подставив ID человека:

```sql
SELECT id, person_id, last_name, first_name, middle_name, phone, created_at
FROM requests
WHERE person_id = 1002
ORDER BY created_at;
```

## Redis (кэш)

Redis кэширует ответы `/api/guess/range` и `/api/guess/item?id=...` (cache-aside, TTL 60 секунд, настраивается через `CACHE_TTL` в `docker-compose.yml`). После сохранения новой анкеты ключ диапазона `guess:range` сбрасывается. Если Redis недоступен, приложение работает без кэша.

Смотреть логи Docker:

```bash
docker compose logs -f web-app
```

Заглянуть в Redis:

```bash
docker compose exec redis redis-cli keys '*'
docker compose exec redis redis-cli get guess:range
docker compose exec redis redis-cli ttl guess:range
docker compose exec redis redis-cli monitor
```

Источник кэша также виден в заголовке `X-Cache: HIT|MISS` (DevTools → Network).

## Тест

Контейнер `test` генерирует данные анкеты через Faker (Python), заполняет форму через Selenium и проверяет БД, паспортную запись, поиск по телефону и работу Redis-кэша.
